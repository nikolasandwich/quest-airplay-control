# Quest 投屏与鼠标 0.2.1

2026-09-12，包 `com.questlab.airplayreceiver`，versionCode 8。

## 已安装的功能

- 保留上下渐进滚动，新增左右 ACTION_SCROLL/HSCROLL 到鼠标横向拖拽的映射。
- 同页新增“左滑（拖拽）”“点击当前指针”“右滑（拖拽）”。没有全局拦截扳机，因此操作其他 UI 按钮不会附带重复点击。
- 点击作用于 **iPad 当前鼠标指针位置**；没有射线坐标到 iPad 坐标的映射。
- 横向发送标准鼠标左键按下、十步相对 X 移动、左键松开，每步 ±24，总量 ±240。它是鼠标拖拽，能否翻页取决于目标应用及 iPad 设置，不是触摸数字化器手势，也不是横向滚轮。

Apple 将鼠标拖拽描述为按住项目并移动鼠标；因此不能把此协议动作直接等同于手指滑页。[Apple 鼠标操作说明](https://support.apple.com/en-gb/guide/ipad/ipada39e5184/ipados)

## 输入证据和生命周期

- 对旧 Probe 原始日志重新做只读统计，759 条 ACTION_SCROLL 中有 99 条非零 HSCROLL，范围 -0.3375～0.2829。原摘要只统计 VSCROLL，遗漏了这些真实横向事件。
- Android 将二维滚动作为 ACTION_SCROLL 的 HSCROLL/VSCROLL 相对增量提供；没有使用屏幕 X/Y 位置冒充原始摇杆轴。[MotionEvent 文档](https://developer.android.com/reference/android/view/MotionEvent)
- 横向主方向与纵向区分，同一连续横向输入段只触发一次动作；归零或新事件到来时观察到足够间隔才重新允许。没有后台定时器凭空产生新手势。
- 鼠标动作在 ACK 后逐步推进。失焦、暂停、取消、超时后只允许松开报告；正常输入与鼠标动作互斥。
- 松开在必要时可绕过普通滚动背压，但保留通知 FIFO，使迟到的按下 ACK 不会被误当作松开成功。松开尝试最多三次；仍无法确认则停用控制并请求断连，提示重新连接。物理链路已经失效时无法保证远端收到松开，程序会丢弃旧动作而不是在下一连接重放。
- 配对、GATT Report Map 和服务顺序保留。一次覆盖安装后系统临时将 Report 分配到178；仅停止应用进程、等 GATT 撤销并重新启动后，恢复到原 Report151/CCCD153 等句柄。没有清配对或重启头显。

## Waiting for AirPlay 修复与实际验证

之前视频有连续输出提交，但帧呈现通知没有让界面更新。现在保留帧回调，并在没有确认时尝试读取视频 Surface 的一个缩小像素；成功表示视频生产者已经提供实际缓冲。读取只在内存中进行，不保存图片。连接成功或仅提交输出不会直接隐藏提示。[PixelCopy 文档](https://developer.android.com/reference/android/view/PixelCopy)

界面在广播、恢复和重新附接时读取服务的当前 hasFrames 状态，避免把迟到的广播或漏掉的通知当作当前状态。

最终进程 PID18989 的日志在 **04:16:08.962** 出现 `surface buffer confirmed by PixelCopy`。随后只读 UI 层级检查确认 `waiting_text_present=false`，投屏区正常保留，七个控制按钮存在。这证明等待覆盖层已隐藏，不等同于完成所有画质/声音/前后台场景验收。
